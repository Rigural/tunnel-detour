# Requirement coverage

Each `rNNN_…` test owns the acceptance criterion below. Scenario assertions belong to that
owner; running an owner on another authorized environment is additional validation, not a new test.
Ordinary Cargo tests intentionally skip laboratories and SDK checks. A skip is not acceptance.

| Tier | Command | Boundary |
| --- | --- | --- |
| Unit / configuration | `cargo xtask test` | Rust policy, real temporary files and configuration validation |
| Network | `cargo xtask test-network` | Isolated Linux namespaces, WireGuard, nftables, DNS, TLS and AdGuard |
| OpenWrt | `cargo xtask test-openwrt` | Native 25.12.6 UCI, rpcd, procd, netifd and real DNS frontends; x86 laboratory |
| SDK | `cargo xtask package --sdk /path/to/sdk` | Reference-target APK generation and inspection |

Core owners live in `sources/core/tests/requirements.rs`, configuration owners in
`sources/service/tests/configuration.rs`, network owners in `sources/service/tests/network.rs`,
and OpenWrt owners in `sources/xtask/tests/openwrt.rs`. The stable numeric prefix identifies the
full descriptive test name. SDK packaging is owned by `sources/xtask/tests/package.rs`.

with synthetic inputs. Its oracles check normalization/valid-state round trips, capacities,
unauthorized allocation and durable-state preservation. The journal helpers are enabled only
by the development `fuzzing` feature and perform no recovery, filesystem or API operations.
Bounded campaigns supplement the owning requirement tests; a campaign without findings is
not proof that all parser paths or recovery transitions have been covered.

messages also require visual acceptance against the native laboratory; record the result
separately from automated rpcd ACL coverage. Native x86 results do not establish target-device
acceptance. Physical-router installation, updates and live traffic checks are a separately
authorized phase; keep their access details and results private.

separate acceptance phases. A desktop mobile-width viewport does not prove handset behavior.

above; HTTP/3, ECH, alternate binding endpoints and generalized DNS filters are not supported.
